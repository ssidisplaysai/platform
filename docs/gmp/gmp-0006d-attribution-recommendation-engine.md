# GMP-0006D Attribution, Recommendations & Decision Support Engine v1.0

## Objective
Implement a governed, deterministic, replayable recommendation layer that consumes only GMP-0006C Evidence Snapshots and produces explainable operator decision support artifacts.

## Constitutional Boundary
The engine:
- Consumes only `GmpEvidenceSnapshot`, `GmpEvidenceCompiledMetric`, and `GmpEvidencePublicationReference` artifacts.
- Does not read raw provider observations.
- Does not mutate evidence snapshots.
- Does not perform autonomous publishing, SEO mutation, or content generation.
- Persists lineage and replay data for reproducibility.

## Architecture

Evidence Snapshots
-> Attribution Engine
-> Insight and Rule Evaluation
-> Recommendation Engine
-> Decision Support Summaries
-> Operator Review Lifecycle

### Attribution Layer
Services:
- `AttributionEvidenceService`
- `AttributionRuleService`
- `AttributionEngineService`

Attribution dimensions (v1):
- Publication
- Site
- Project
- Channel
- Page
- Campaign (placeholder)
- Search
- Organic
- Referral
- Direct
- Custom Source

Attribution is snapshot-scoped, windowed, deterministic, and lineage-stamped.

### Recommendation Layer
Services:
- `RecommendationCatalogService`
- `RecommendationEvaluationService`
- `RecommendationEngineService`

Recommendations are generated by deterministic, versioned rules and are immutable records.

Recommendation fields include:
- Recommendation ID
- Rule ID
- Rule version
- Evidence snapshot ID
- Confidence
- Severity
- Priority
- Category
- Explanation
- Supporting evidence
- Recommended action
- Creation timestamp

### Rule Catalog
Rule catalog is persisted and versioned independently from recommendation runs.

Each rule records:
- Identifier
- Version
- Description
- Inputs
- Thresholds
- Output schema
- Severity mapping
- Priority mapping
- Replay compatibility

Initial deterministic rules:
- `improve_declining_ctr`
- `refresh_aging_content`
- `investigate_ranking_loss`
- `review_indexing_anomalies`
- `monitor_traffic_decline`
- `validate_publication_consistency`
- `detect_stale_performance`
- `flag_low_confidence_evidence`
- `review_incomplete_collection_history`

### Decision Support Layer
Service:
- `DecisionSupportService`

Deterministic summaries:
- Recommendation summary
- Trend summary placeholder
- Health summary
- Site health
- Project health
- Evidence quality summary

No AI-generated narrative is used.

### Lifecycle and Immutability
Lifecycle states:
- `NEW`
- `REVIEWED`
- `ACCEPTED`
- `REJECTED`
- `DISMISSED`
- `EXPIRED`

Lifecycle transitions are append-only records in `GmpRecommendationLifecycleEvent`.
Recommendations are immutable and never overwritten.

### Version and Lineage Model
Recommendation lineage tracks:
- Recommendation version
- Rule version
- Evidence compiler version
- Snapshot version
- Attribution version
- Rule execution checksum
- Recommendation immutable payload checksum

### Replay Model
Given:
- Evidence Snapshot ID
- Rule Catalog Version
- Attribution Version

Replay produces deterministic output checksums and stores replay history with match indicators against prior runs.

- Full workspace TypeScript strict checks still surface pre-existing non-GMP-0006D debt in unrelated GOP/publishing files.
- Campaign attribution remains a governed placeholder dimension pending future package definitions.
