# GAR-0002A Canonical Hash Correction

## Package
- Program: Genesis Internal Enterprise Architecture Audit
- Package: GAR-0002A
- Scope: GAR framework defect correction only

## Root Cause
GAR-0002 baseline integrity comparison hashed raw GAR-0001 working-tree bytes.

On Windows, Git checkout uses CRLF in working tree (`w/crlf`) while repository/index blobs are LF (`i/lf`).
This produced false-positive hash drift despite identical committed content.

## Correction Implemented
Chosen method: **Option A (preferred)**, canonical Git blob hashing.

Implementation details:
- GAR-0001 baseline hashes in GAR-0002 are now computed from canonical repository blobs using:
  - `git show HEAD:<repo-relative-path>`
  - `sha256(blob-bytes)`
- Raw working-tree byte hashing for GAR-0001 baseline verification was removed from GAR-0002.
- GAR-0002 run manifest now records:
  - `gar0001HashingMethod: "git-blob-canonical-sha256"`

## Why Platform-Independent
Git blob content is canonical repository object content and is independent of local checkout EOL conversion.
Therefore:
- Windows CRLF working tree and Linux LF working tree resolve to the same canonical blob hash.
- Baseline integrity verification is deterministic across platforms.
