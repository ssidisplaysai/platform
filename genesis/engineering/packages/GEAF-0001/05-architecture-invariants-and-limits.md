# 05 Architecture Invariants And Limits

## Invariants
1. Architecture before implementation.
2. Governance before execution.
3. Determinism and traceability are mandatory.
4. Authority flows downward through constitutional layers.
5. Upstream meaning cannot be redefined downstream.

## Limits
1. No runtime behavior specification in framework package scope.
2. No compiler algorithm implementation in framework package scope.
3. No API/persistence/deployment/infrastructure definitions.
4. No enterprise-application business logic absorption.
5. No modification of certified GSTP evidence artifacts.

## Runtime Limit Mapping
AFR-0004 constrains future work to extension/composition/integration and prohibits runtime foundation redesign without governance supersession.
